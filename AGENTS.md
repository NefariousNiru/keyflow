# AGENTS.md — Remote Keyboard

## Mission
Build a native, local-only Android keyboard for Windows that appears when the desktop focuses an editable field. Develop natively on Windows. Production targets are Windows 10 22H2 (build 19045) x64 and Windows 11 x64 on supported releases; Android is the sole mobile target. Linux, macOS, Windows ARM64 and x86 are out of scope for MVP. Windows 10 compatibility does not imply Microsoft security support; recommend current security updates/ESU where applicable. No cloud, accounts, ads, analytics, or remote desktop streaming. Read MILESTONE.md before work. Implement one milestone at a time, with tests and evidence; do not mark untested behavior as working.

## Architecture and stack
- Desktop: C# on .NET 10 LTS; platform-neutral testable core and a Windows-specific adapter. Windows tray via WinForms, UI Automation, Win32 SendInput, DPAPI CurrentUser. Run as an ordinary interactive user, not a Windows service or administrator.
- Android: Kotlin, Gradle wrapper, Jetpack Compose custom keyboard activity, OkHttp, Android Keystore, network callbacks and connected-device foreground service where permitted. Target current stable Android SDK; initially support API 29+ and test physical Samsung devices.
- Transport: direct TCP/TLS or authenticated WSS; prefer TLS 1.3 on Windows 11, allow TLS 1.2 with ECDHE and AEAD on Windows 10; reject older versions and weak cipher suites, verify negotiated parameters and peer identity before application traffic, one long-lived connection, compact versioned messages; choose one framing approach in milestone 0. No public listener, relay or internet dependency. Use maintained crypto libraries and OS entropy.
- Development: Windows-native .NET and Android SDK tooling; use an in-process synthetic focus/input harness for protocol tests. Verify .NET/runtime and dependency compatibility with Windows 10 22H2 during M0. Do not add another desktop platform or standalone development host.

Core owns pairing/session state, protocol, connection lifecycle and input validation. Define interfaces for focus monitor, input injector, network policy, secure storage, session lock and lifecycle. OS adapters own native APIs. Keep native key mapping outside transport; use a canonical key enum plus explicit Unicode text events. No generic remote command execution, file transfer, clipboard sync, screen capture, or arbitrary OS RPC.

## Mandatory security and privacy
- Pair only when explicitly requested on desktop. Show cryptographically random six-digit OTP; expire after 2 minutes; single use, maximum five attempts per pairing window, global throttling and cooldown. Use a vetted password-authenticated key exchange (PAKE) implementation compatible across both runtimes, binding device keys and protocol transcript, or an audited out-of-band verification design with equivalent protections. Never use OTP as a TLS PSK or send it to an unverified peer. If no suitable implementation exists, stop and document the decision; do not invent crypto or disable TLS validation. Exchange/pin long-term identities only after authenticated pairing. Require mutual authentication thereafter.
- Authorization expires exactly 30 days after successful pairing; no sliding renewal. Reject expired credentials on both sides, including existing sessions, and require explicit new OTP. Persist expiration securely; fail closed on detected clock rollback. Support immediate revocation and replacement; MVP one phone per desktop. Use monotonic session timers where appropriate.
- Persist only identity keys, peer pins, expiry, network preferences and minimal settings; no key content, field values, titles, clipboard contents, event history, analytics or production log files. Transient bounded memory is necessary; discard input immediately after handling. No input payloads in exceptions, traces, crash reports, dumps intentionally generated by the app, or CI artifacts. Do not claim zero RAM use or guarantee OS never pages memory.
- Trusted Wi-Fi selected by user; confirm network identity using available platform metadata (SSID is not authentication). Accept only intended local-interface traffic, restrict firewall scope to private/local network and validate peer endpoints; never expose globally or use UPnP. Stop on network loss/change, lock, pause, revocation or expiration. Android Ethernet/mobile data not a fallback; desktop Ethernet on same LAN may be an explicitly enabled option later.
- mDNS/NSD discovery is untrusted and optional; advertise minimal metadata. Manual LAN IP fallback. Use Android per-network socket binding and desktop source/interface selection when permitted. Respect VPN policy/kill switches; never modify routes, disable VPN or bypass administrator policy. Provide clear local-access-blocked status.
- Strict protocol limits, message validation, authenticated session IDs, ordered sequence numbers, reject replay/stale focus generations. No queued input across reconnects. Rate-limit and bound queues. Release all remotely held keys on disconnect, pause, expiry, focus invalidation or timeout; do not release keys not owned by this session where feasible. Never inject on locked/secure desktop or elevate to bypass UIPI.
- Password fields: never read values; suppress automatic activation by default, with explicit user-controlled manual mode if allowed by OS. Exclude sensitive apps via local settings. No global keyboard capture.

## User experience and lifecycle
- Windows installer: self-contained x64 setup EXE (e.g. Inno Setup), per-user install, startup opt-in, uninstall removes startup/firewall entries and offers removal of pairing credentials. No separate runtime installation. Tray menu: status, pair/revoke, trusted network, pause/resume, manual keyboard, exit. Pair window displays OTP and expiry. No main dashboard.
- Windows focus: event-driven UIA focus notifications, inspect only control type, editable/read-only/enabled/password metadata; use bounded asynchronous work and debounce. Handle clicks in already-focused editable fields through a minimal mouse event fallback if needed; never collect coordinates/history beyond immediate processing. Check focus/session before injection. Avoid repeated wake requests, handle non-editable transitions, manual mode for terminals/custom controls. No promise of universal application coverage.
- Android: setup/pairing screen, keyboard surface, status/permission controls and required foreground notification. Auto-show/hide on authenticated focus transitions, manual notification action, dismiss suppresses reopening until a fresh focus/click event. Opt-in wake/lock-screen mode; evaluate companion association eligibility and documented background launch exemptions, setShowWhenLocked/setTurnScreenOn only when launch allowed. Never dismiss secure keyguard or fake alarm/call notifications. If launch denied, use notification tap fallback. Respect force-stop, Doze and OEM restrictions; document reboot and Samsung battery settings. No permanent wake lock or continuous polling.
- Keyboard: QWERTY, digits, punctuation, Unicode text, Esc, Tab, Enter, Backspace, Delete, F1–F12, Ctrl/Alt/Shift/Win, Home/End/PageUp/PageDown, arrows; sticky/held modifiers, key repeat with cancellation, optional haptics, portrait/landscape. Distinguish text commits from key down/up and shortcuts. No predictive learning, remote clipboard or Android IME integration for MVP.
- Reconnect with bounded exponential backoff and jitter; respond to network/sleep lifecycle events. Keep connection alive with modest heartbeat and watchdog. Never replay old keystrokes. Manual mode must remain explicitly armed, scoped to unlocked active session; deactivate on unexpected foreground change or timeout. Automatic mode uses focus generation tokens and revalidates target before typing.

## Engineering workflow
- Before each milestone: inspect repo, summarize design, update ADR if architecture changes. Implement small reviewable increments; unit and integration tests first for security-sensitive logic. Use clear names and docstrings for public interfaces and non-obvious platform behavior.
- Keep dependencies minimal, pinned and licensed; no custom crypto, unnecessary framework, database or cloud service. No TODO stub in production path, no silent catch-all, no secret in source. Use synthetic test payloads only.
- Prefer async I/O and event subscriptions; cancel tasks, unregister listeners and close sockets on teardown. Benchmark release builds: target desktop idle CPU <1% averaged over 5 min, idle working set <60 MB (target, not guarantee), LAN key-to-injection p95 <50 ms, awake activation p95 <500 ms; record hardware/network and actual measurements. Measure Android battery drain over idle baseline; no persistent wake lock. Do not sacrifice security for these targets.
- CI: Windows core and native integration tests and self-contained publish/installer, Android lint/unit tests and APK build. Pin workflow actions, minimal permissions, dependency scanning; no release secrets in PR workflows. On version tags produce signed APK (stable signing key stored in protected secrets), Windows x64 installer for both Windows 10 and 11 (Authenticode if available, otherwise clearly unsigned), SHA-256 checksums and release notes. Never label unsigned Windows binaries signed. Keep signing keys out of artifacts.
- Work on feature branches; do not merge or publish releases without explicit authorization. Keep milestone checklist current with test commands, actual evidence, blockers and known limitations. Do not claim physical device/Windows GUI tests ran when unavailable. GitHub-hosted Windows runners are Windows Server, not proof of desktop compatibility; require manual or dedicated VM/device validation on Windows 10 22H2 and Windows 11 before release.
- Final README: clean modern Markdown, actual features and screenshots only, install/pair/use, VPN and lock-screen limitations, privacy model, supported OS/device matrix, local build/test, release downloads and troubleshooting. No invented benchmarks or compatibility claims.

## Windows compatibility policy
- Use a single x64 Windows installer and codebase for both OS versions. Guard any newer API with runtime capability detection; provide a safe fallback or clearly report unsupported features.
- Test installation, startup, tray, UIA focus, input injection, session lock, discovery, VPN, sleep/resume, TLS negotiation and uninstall on both desktop versions. Use Windows 10 22H2 as the minimum baseline, not all historical Windows 10 builds.
- Do not disable Windows security features or change global TLS settings to make compatibility tests pass.
