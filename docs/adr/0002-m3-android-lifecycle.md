# Android keyboard activation and lifecycle

The user starts the connection from KeyFlow's visible setup screen. A connected-device foreground service owns the authenticated LAN session. The service also declares the location foreground type so Android can supply trusted Wi-Fi identity metadata while setup is in the background. KeyFlow requests no location samples and holds no wake lock. The ongoing notification opens setup, offers the keyboard when a valid focus exists, and stops the connection.

Keyboard visibility and input are scoped to the authenticated session and focus generation. A new focus replaces the old target. Blur, disconnect, session pause and expiration clear it. Dismissal releases keys and suppresses reopening until a fresh focus or an explicit phone action. Every input batch passes through the current focus, keyguard and connection checks. Pending batches are bounded and discarded on focus changes, release and disconnect. The desktop still validates input with its own session state.

KeyFlow attempts an automatic launch when setup is visible or Android has a current companion association for the paired desktop. Android 13 and later can associate a discoverable Bluetooth desktop through the OS chooser. The user confirms the desktop and KeyFlow ties the returned association ID to the currently authenticated TLS pin. The companion still communicates over Wi-Fi. Android's ordinary Bluetooth association records the user's selection. The TLS pin and existing authorization continue to establish transport identity. A third-party app cannot create a self-managed association using the Android privileged permission. [Android companion pairing](https://developer.android.com/develop/connectivity/bluetooth/companion-device-pairing) · [AOSP permission declaration](https://android.googlesource.com/platform/frameworks/base/+/android17-release/core/res/AndroidManifest.xml)

Screen wake and presentation above keyguard require explicit opt-in and an eligible automatic launch. An activity with eligible wake flags leaves the secure keyguard in place and disables typing until unlock. When automatic launch is unavailable or Android blocks it, a generic notification opens the keyboard for the current focus. The app avoids full-screen intents, background location permission, battery exemption requests and boot-time service startup. The user starts the service again after reboot or force-stop. Android may suspend network access in Doze or under OEM battery restrictions. [Android background activity starts](https://developer.android.com/guide/components/activities/secure-bal)
